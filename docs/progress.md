- **What the M7 build + review actually established, worth keeping:**
  - **The independent appsec pass found a real bypass the fully-green suite never asked about — the corridor-class bug, M3's lesson recurring.** All 8 crown-jewel invariants were confirmed enforced, but `counter` was the one write path that *created a new priced `Offer` row* (D1's design) without re-checking listing liveness, while `create` (A3) and `accept` (B8) both did. - **M4 decisions to remember:** the public view took the canonical path — `GET /api/listings/{id}` is public (live only), and the owner's full view **moved** to `GET /api/my/listings/{id}`. `ListingPublic` is a **standalone** model, deliberately *not* a `ListingRead` subclass, so a private field added to the owner's view cannot join the public one. `status` is **not** on the public model (browse returns `live` only, so it would be a constant and a channel for a future state to leak); M12 may add a deliberate public "under offer" flag. - **Money range filters cast to NUMERIC.** The `Money` TypeDecorator stores Decimal as TEXT, so a bare SQL comparison is lexicographic (`'90000.00' > '200000.00'` is true as strings).
