- 2026-07-19 — **M3 added to the security-critical list, and the list demoted to a floor** (Article 3 §3). The list (`M1/M2/M5/M7/M8/M10`) was an enumeration written at planning time, predicting which milestones would prove security-relevant. It was wrong about **M3**: admin curation owns `require_admin`'s first real consumer, owns the only path to `live`, and is the first milestone to serve `ListingPrivate` to anyone but its owner — yet it was not on the list. It received the independent `appsec-engineer` pass only because a **stale note in `progress.md` wrongly claimed it was on the list**, and that pass found a **blocking curation bypass**: a seller could republish unreviewed content via pause → edit → resume, because the edit-resets-review guard fired on `live` but not `paused`. *Following the list literally would have shipped it.* **Two changes, not one.** (1) M3 joins the list (now `M1/M2/M3/M5/M7/M8/M10` — 19 occurrences of the compact form across 13 files). *The first sweep missed `docs/git_strategy.md` §Branch review, which spells the list out longhand rather than in the compact form the find-and-replace matched — caught by the first `docs-auditor` run, and a fair illustration of why "updated everywhere" is a claim that needs checking rather than asserting*. (2) More importantly, the list is no longer the whole mechanism: `scripts/check_appsec_trigger.py` reads the **diff** and requires a pass whenever the branch touches a permission boundary, a route, a response model, a state transition, an upload path, money or websockets — wired into `/dod` and `/run-milestone`. **A list predicts; a diff describes.** The list remains a floor the trigger can only escalate, never excuse. **Recorded alongside it, in `specs/003-admin-curation/spec.md` as criterion E6:** the milestone's forbidden-path tests each named *one* door and missed the corridor, so the bypass class is now covered by a **reachability test** that walks every sequence of up to three seller actions and asserts the invariant (*a seller cannot publish content an admin has not seen*) — verified by reverting the fix, whereupon it fails, catching the bypass at depth 2 (`paused → edit → resume`). **The general rule:** when a review finds a bug your tests missed, fix the bug, then ask what *class* of question your tests were not asking.
